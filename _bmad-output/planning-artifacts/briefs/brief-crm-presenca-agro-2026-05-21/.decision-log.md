## Decisões cravadas durante party-mode

### Arquitetura
- **Multitenant lógico** via `tenant_id` + Postgres RLS (não DB-per-tenant)
- **Stack mobile:** Expo + PowerSync (não WatermelonDB — trocou após análise de trade-off)
- **Backend:** Nest.js + Prisma + Postgres + PostGIS + RLS + Better-Auth + R2 + BullMQ
- **Frontend web:** React + Vite + TS + TanStack Router/Query/Store + Tailwind 4
- **Monorepo Turborepo:** apps/mobile + apps/web + apps/api + packages/types/schemas/sdk/domain
- **PDF:** Template fixo (Puppeteer + HTML/CSS) — editor visual fica pra futuro
- **Mapas:** Mapbox GL JS (web) + Mapbox GL Native (mobile), PostGIS pra geo

### Produto
- **App-first** (não CRM-first) — usuário primário é consultor de campo
- **3 tipologias de visita na Fase 1:** plantio + previsão de colheita + monitoramento de pragas (adubo cortado)
- **Cadastro contextual** ("você está em uma fazenda nova? cadastra agora?") usando GPS
- **Cadastro progressivo / Conversational Wizard** (estilo Typeform, não chat puro)
- **CRM web tem peso próprio:** demarcação de talhões + dashboard gestor + relatórios consolidados (não só ferramenta de mapa)
- **Quem fecha a safra:** consultor ou admin

### Modelo de Negócio
- **2 ICPs:** revenda (primário) + autônomo (freemium controlado)
- **Billing:** 2 SKUs binários (revenda paga por seat / autônomo paga individual ou freemium)
- **Fluxo bottom-up:** piloto = consultor individual de revenda que paga sozinho e vira champion interno pra revenda absorver depois

### Discovery / Pilotos
- **1 conhecido** identificado (consultor de revenda, multi-cultura — culturas exatas a confirmar)
- Status do piloto: "se eu pedir, ele topa" — ainda não combinado formalmente
- Mary recomendou meta de 3 pilotos em 30 dias; John recomendou 1 + busca de 2 estranhos em paralelo. **Decisão final pendente** (afetada por runway indefinido).

### Runway / Contexto
- **Sem pressão de faturar** — runway indefinido, foco em "bom produto" sobre prazo
- Fator limitante muda de dinheiro pra motivação/discovery
